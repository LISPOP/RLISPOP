General strategies for data cleaning.

Inspect data after import.

It is essential to inspect data-sets after importing them to get a feel for what you are dealing with and to spot problems and to ensure your import has worked properly.

After every import you should run: glimpse(), summary(), str(), tail() and head() to get a glimpse.

Ask yourself these questions:

  1. How many variables are there? How many rows are there? Do those make sense? Did anything get missed? Did anything superfluous get imported? If so, go back and modify your import command by skipping lines etc.

  2. What are the classes of the variables that you are interested in? Are variables that should be numeric actually stored as numbers (e.g. numeric, integer or double) . Are date variables already stored as date?

  3. Do you see any immediate duplicate or messed up values in your inspection?

  4. Are there any high levels of missing values? the summary() command often provides this information. Are there no missing values somewhere? That could be a problem; missing values should be stored as NA but they may have been imported simply as white-space.

Instead, running table() or factor() on a character or factor variable can quickly give you information you need.

table(iris$Species)

    setosa versicolor  virginica 
        50         50         50

Running table() counts the number of instances of each unique value. So, you quickly see that you are dealing with the categories: setosa, versicolor and virginica. Right away you will see any spelling mistakes.

The factor() command prints out all of the values, but it conlcudes with a nice report of the individual levels of the factor, which is effectively the same information as reported in table() so it can be useful.

Examining your work

Coding is always an iterative process. You find problems, try solutions, inspect the solutions and, when they work, save the results.

Each step requires a slightly different approach.

Inspecting solutions

Suppose we want to collapse the species here into two. This the correct command, but the results that are spit out are hard to diagnose. To test the results, we could slap a view() on at the end.

# iris %>% 
#   mutate(Species2=Recode(Species,"'versicolor'='setosa'")) %>% view()

Or, we could potentially just save the dataset somewhere and then inspect it. If it works, then we can just modify the script.

iris %>% 
mutate(Species2=Recode(Species,"'versicolor'='setosa'")) ->test
table(test$Species2)

   setosa virginica 
      100        50 
#Now repeat, but resave the dataset over the old one. 

iris %>% 
mutate(Species2=Recode(Species,"'versicolor'='setosa'")) ->iris
